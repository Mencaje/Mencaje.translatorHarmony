# 大模型资源：7-Zip 分卷压缩与解压说明

本仓库部分离线模型单文件体积较大（例如 `model.bin` 约 2.35GB），超过 GitHub LFS 单文件 2GB 上限，也不适合作为单个文件推送到 Gitee（单文件约 100MB 限制）。**请使用 7-Zip 分卷压缩**，将大文件拆成多个小卷后再放入仓库对应目录提交。

---

## 一、需要分卷的文件（示例）

| 原文件 | 约大小 | 建议分卷目录 |
|--------|--------|--------------|
| `third_party/models/nllb-ct2-download/nllb-200-distilled-600M/model.bin` | 2.35 GB | `third_party/models/nllb-ct2-download/nllb-200-distilled-600M/` |
| 其他超过 95MB 的单体二进制 | 视情况 | 与原文件**同一目录** |

> 已存在且体积合规的文件（如 `nllb200_distilled_600m.zip` 约 1.47GB）可按现有方式处理；**新上传超大单文件请优先用分卷方案**。

---

## 二、压缩前准备

1. 安装 **[7-Zip](https://www.7-zip.org/)**（Windows 推荐官方安装包；macOS 可用 `p7zip`）。
2. 确认待压缩的**完整原文件**在本地已就绪。
3. 在资源目录下新建或使用**同一文件夹**存放分卷，例如：

   ```
   third_party/models/nllb-ct2-download/nllb-200-distilled-600M/
   ├── model.bin          ← 压缩前的原文件（压缩完成后可删除，勿提交原文件）
   ├── model.bin.7z.001   ← 分卷 1（提交）
   ├── model.bin.7z.002   ← 分卷 2（提交）
   └── ...
   ```

**重要：所有分卷必须位于同一目录内**，文件名前缀一致，仅序号不同。

---

## 三、使用 7-Zip 图形界面分卷压缩

1. 在资源管理器中**右键**待压缩文件（如 `model.bin`）。
2. 选择 **7-Zip → 添加到压缩包…**（*Add to archive…*）。
3. 在对话框中设置：
   - **压缩格式**：`7z`
   - **压缩等级**：`标准` 或 `最快`（模型权重对压缩率不敏感，优先速度）
   - **分卷大小**（*Split to volumes, bytes*）：
     - 若主要推 **Gitee**：填 `95M`（略低于 100MB 上限）
     - 若主要推 **GitHub**：填 `500M`～`900M` 均可（单卷请远小于 2GB）
4. 点击 **确定**，等待生成 `文件名.7z.001`、`文件名.7z.002` …
5. **删除或不要提交**未压缩的原始大文件（仅提交 `.7z.001`、`.7z.002` 等分卷）。

---

## 四、使用命令行分卷压缩（可选）

在 **7-Zip 安装目录**或已加入 PATH 的环境下执行：

```bat
cd third_party\models\nllb-ct2-download\nllb-200-distilled-600M

REM 分卷大小 95MB（适合 Gitee）
7z a -t7z -v95m model.bin.7z model.bin

REM 或分卷大小 500MB（适合 GitHub）
7z a -t7z -v500m model.bin.7z model.bin
```

生成的文件名为：`model.bin.7z.001`、`model.bin.7z.002`、…

---

## 五、解压方法（给克隆仓库的使用者）

1. 从仓库克隆或下载后，确认**所有分卷**（`.7z.001`、`.7z.002`、…）都在**同一文件夹**内。
2. 安装 **7-Zip**。
3. **只需解压编号为 001 的第一个分卷**：
   - 图形界面：右键 `xxx.7z.001` → **7-Zip → 解压到当前文件夹**（或 *Extract Here*）。
   - 命令行：

     ```bat
     7z x model.bin.7z.001
     ```

4. 7-Zip 会自动读取同目录下的 `.002`、`.003` 等后续分卷，还原出完整原文件（如 `model.bin`）。
5. 解压完成后再按项目 README 构建/运行应用。

> **切勿**只拷贝部分分卷到别的目录再解压；缺卷会导致解压失败或文件损坏。

---

## 六、提交与推送建议

- 分卷文件可随普通 Git 提交（无需 LFS 的单卷若小于平台限制）。
- 超大资源**分批、分目录**提交，避免一次 push 过多 GB。
- 在 PR 或 Release 说明中注明：需先合并分卷解压，再执行 `scripts/` 下相关准备脚本。

---

## 七、常见问题

**Q：能否用 WinRAR / zip 分卷？**  
A：本说明以 **7-Zip（.7z 分卷）** 为准，便于跨平台与命令行自动化；若改用其他格式，请在目录内附 `README` 说明格式与解压工具。

**Q：解压时提示「无法打开文件」？**  
A：检查是否所有分卷齐全、是否在同一目录、001 文件是否完整下载。

**Q：GitHub LFS 还要用吗？**  
A：分卷后单文件变小，多数情况可用普通 Git 提交；仍建议单卷控制在 **< 100MB（Gitee）** 或 **< 1.9GB（GitHub LFS 安全线）**。
